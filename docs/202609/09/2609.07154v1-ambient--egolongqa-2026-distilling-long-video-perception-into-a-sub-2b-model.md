## 摘要
我们描述了我们在ECCV 2026可穿戴AI挑战赛EgoLongQA赛道中的参赛方案，该方案在<=2B参数组中排名第一，在保留测试集上得分为0.8279。我们的系统是一个单一的2B视觉语言模型，能够以一次贪婪前向传播回答关于十分钟自我中心视频的多项选择题；它是通过将工具使用型智能体流水线的初级感知模块（而非智能体本身）蒸馏到一个小型学生模型中获得的，使用的教师轨迹已过滤为回答正确的那些。它达到了大型智能体流水线准确率的89%，而参数量仅为后者的1.1%。这将基础模型从27.1%提升至我们保留问题的81.4%。2B主干网络拥有2.2132B参数，因此超过了分组限制。为使参赛有效，我们将多语言嵌入表从248,320行修剪至143,469行，达到1.9985B参数，并且在保留行上的逻辑值可证明相同。

## Abstract
We describe our entry to the EgoLongQA track of the Wearable-AI Challenge in ECCV 2026, which placed first in the <=2B parameter division with 0.8279 on the held-out test set. Our system is a single 2B vision-language model that answers multiple-choice questions about ten-minute egocentric videos in one greedy forward pass; It is obtained by distilling the junior perception module of a tool-using agentic pipeline, not the agent itself into a small student, using teacher traces filtered to those that answered correctly. it reaches 89% of the accuracy of the large agentic pipeline using 1.1% of its parameters. This raises a 27.1% base model to 81.4% on our held-out questions. The 2B backbone has 2.2132B parameters and therefore over the divisional limit, to make the entry admissable we prune the multilingual embedding table from 248,320 to 143,469 rows, reaching 1.9985B with provably identical logits on retained rows.

论文的核心答案是：**可以**——但关键不在于蒸馏整个智能体，而在于只蒸馏其中“可被单次前向模仿”的初级感知模块。该方法在 EgoLongQA ≤2B 参数组夺得第一名（0.8279），用 1.1% 的参数达到了大型智能体流水线 89% 的准确率，为低资源长视频问答提供了一条可行的技术路径。

## 2. 论文提出的方法论

### 核心思想

> **不要蒸馏智能体本身，而是蒸馏智能体中“输入输出契约可被单次前向表达”的组件。**

论文将一个工具型智能体流水线拆成两个部分：

- **初级感知模块（junior perception module）**：输入 100 个均匀采样的视频帧 + 问题 + 选项，一次前向输出推理与答案。该模块被采样 3 次。
- **高级编排器（senior orchestrator）**：当 3 次初级采样结果不一致时被调用，拥有调用工具（如 focus_clip / search_clip）的能力，可对视频中的特定时间区间进行高保真感知，通过多轮工具循环解决分歧。

作者发现：初级感知模块的输入/输出协议与学生模型在推理时接收到的协议完全一致，**零训练测试不匹配**；而高级编排器的多轮工具轨迹无法在单次前向传播中表达，因此**不可模仿**。最终选择只蒸馏初级模块。

### 关键技术细节

#### 1. Oracle 过滤的轨迹蒸馏（Oracle-filtered trace distillation）

- 从教师流水线在训练视频上的记录轨迹中，只保留**<choice> 与 ground truth 一致**且**三次初级采样结果一致**的轨迹。
- 最终得到 **2,936 条轨迹，覆盖 605 个视频**，每个问题中位数有 5 条不同描述。
- 教师模型全部为开放权重模型（见表 1），未使用任何闭源模型（作者说明这让最佳闭源初级模型的对比损失约 1.4 个百分点）。

> **蒸馏策略的经验依据**：作者在门控级联机制下分别统计了两条路径的表现：
> - 初级一致（跳过高级）：占样本 60–66%，准确率 91–95%
> - 升级到高级+工具：占样本 34–41%，准确率仅为 63–67%
>
> 这说明流水线的大部分准确率本来就来自初级模块；高级模块只处理最难的那部分残差，准确率反而低。

#### 2. 学生模型与训练设置

- 学生模型：Qwen3.5 家族的 2B 视觉语言模型。
- 训练方法：LoRA（r=16, α=32），1 个 epoch，cosine 学习率调度，batch size 1 + 梯度累积 8。
- 损失加权：对输出中 <choice> 标记段施加 **3× token 权重**。作者发现权重降为 1.0 在所有评测上均更差。
- 输出格式：带时间戳的自由文本视频描述 + 结构化答案（包含 <choice>、<reason>、<citation>），与教师初级模块的“preempt-answer”工具契约完全相同。

#### 3. 分辨率迁移（Resolution transfer）

- 训练时 max_pixels=50176（约 64 vision tokens/帧）。
- 推理时 max_pixels=331776（约 423 tokens/帧）。
- 迁移收益：+5.8 个百分点（对比训练和推理都在低分辨率下进行）。
- 作者解释：适配器学到的是任务而非分辨率，因此训练成本降低约 6 倍而无精度损失。

#### 4. 合成数据（Synthetic data）

- 使用 Ambient 智能体在 408 个 Ego4D 视频上生成 **943 条经过审计的多选题**。
- 生成流程包含两道关键过滤：
  - **对抗性拒绝**：拒绝不依赖视频即可回答的问题（防止数据集偏差泄漏）。
  - **帧级证据验证**：确认证据在帧中确实可见。
- 原始生成器的输出 42% 为“A”，经字母平衡后变为近似均匀分布（26%）。作者强调这一步并非可有可无——原始偏差是极易被模型学到的。

#### 5. 先验校正评估（Prior-corrected evaluation）

- 验证集的黄金标签分布严重倾斜：**每题都选 C 可得到 63.4% 的准确率**。
- 作者通过打乱选项构造了黄金分布近似均匀的保留集，用于隔离“感知能力”与“选项先验”。
- 关键发现：监督蒸馏会把 benchmark 自身的答案先验迁移给学生（见下表）：

| 模型 | 准确率 | 预测 C 的概率（gold 为 27%） |
|---|---|---|
| 2B base | 49.4% | 19% |
| + 蒸馏（真实轨迹） | 53.8% | 40% |
| + 蒸馏 + 合成数据 | 56.6% | 26% |

- 合成数据不携带原 benchmark 的答案先验（预测 C 率 26% ≈ gold 率 27%），有助于提升分布外鲁棒性。

#### 6. 词表修剪以满足参数限制（Vocabulary pruning）

- 学生骨干网络为 **2.2132B 参数**，超出 ≤2B 限制。构成如下：

| 组件 | 参数 | 占比 |
|---|---|---|
| 语言层 | 1373.3 M | 62.0% |
| 嵌入表（248,320 × 2048） | 508.6 M | 23.0% |
| 视觉塔 | 331.4 M | 15.0% |
| 总计 | 2.2132 B | 超限 |

- 嵌入表为多语言词表，占参数 23%，但任务并不需要多语言能力。
- 修剪方法：
  - 保留 token id [0, 143000) 不变；
  - 附加一小批显式保留的稀有 token；
  - 重新定位 33 个附加 token 和特殊 token，逐行精确复制嵌入向量；
  - 词表从 248,320 行减至 **143,469 行**，总参数量降至 **1.9985B**，低于限制约 150 万参数；
  - tokenizer 保持原样，模型代码在嵌入查找前对 id 进行重映射。
- 效果：保留行上的 logit 差异**严格为 0**；在 70 个保留样本上以服务分辨率解码输出**字节级一致**。

### 算法流程（文字说明）

1. 对每个训练视频，运行大型智能体流水线：初级模块均匀采样 100 帧并输出答案（重复 3 次）。
2. 若 3 次结果一致，流水线直接提交，不调用高级模块。
3. 若不收敛，则调用高级模块（带工具）解决分歧。
4. 从记录中**仅保留初级模块中回答正确且两次或三次一致的轨迹**作为蒸馏数据。
5. 额外用合成数据管线生成均匀先验的多选题。
6. 以 LoRA 方式用上述数据微调 2B 学生模型，对 <choice> 段施加 3× token 权重。
7. 训练在低分辨率下进行，推理切换到高分辨率。
8. 通过修剪多语言嵌入表将模型压至 2B 线以下，保持输出逻辑不变。
9. 推理时：输入 100 个均匀采样帧 + 问题 + 选项，单次贪婪解码输出答案。

## 6. 主要结论与发现

1. **方向性结论**：将大型工具智能体的“可单次前向的感知组件”蒸馏出来，可以在严格参数约束下保留绝大多数精度——2B 学生达到了大型流水线 89% 的准确率，参数量仅为后者的 1.1%。
2. **幅度结论**：蒸馏使 2B 基础模型从 27.1% 提升到 81.4%（约 3 倍），在 EgoLongQA ≤2B 官方排行榜以 0.8279 取得第一名。
3. **词表修剪可行**：通过修剪 248,320 行到 143,469 行多语言嵌入表，可将 2.2132B 模型降到 1.9985B，保留行上的 logit 差严格为 0，生成输出字节级一致。
4. **先验泄漏是蒸馏中的真实风险**：直接监督蒸馏会把 benchmark 的答案先验迁移进学生模型；选项打乱或合成数据可缓解此问题。
5. **SFT 的 RL 后训练无增益**（至少在该约束条件下），且原因可能在于“分布内且未见过的提示”数量不足。
6. **帧预算的影响取决于模型容量**：更多帧帮助 35B 模型（+11.2 pp），但伤害 ≤2B 模型（−4.4 pp）。
7. **高分辨率推理迁移**：低分辨率训练 + 高分辨率推理带来 +5.8 pp 的提升，训练成本降低约 6 倍。

## 7. 优点

- **设计洞察深刻**：区分“可模仿的组件”和“不可模仿的组件”，将蒸馏目标从“整个智能体”收缩到“初级感知模块”——这一决策在概念上非常清晰，并有数据支撑。
- **零训练/推理不匹配**：学生模型的输入输出契约与教师初级模块完全一致，避免了常见的蒸馏协议失配问题。
- **参数削减方法优雅可验证**：词表修剪保留原始 logit，允许逐位验证，不依赖近似或重训练，具有工程上的严谨性（可证明地不改变保留路径的输出）。
- **评估设计上的自我批判**：明确检测到评测集中的选项先验偏置（全靠选 C 可得 63.4%），并构造了反偏置的保留集，说明作者对 benchmark 自身的偏差有清醒认知。
- **诚实的负结果报告**：将 RL 失败、帧数增加伤害小模型等反直觉结论完整披露，这类内容对社区往往有较大参考价值。
- **低资源可复现性**：全部使用开放权重

- **低资源可复现性**：全部使用开放权重教师模型，无闭源 API 依赖，蒸馏数据量与合成数据量均较小（合计不足 4,000 条），LoRA 训练 1 个 epoch 的成本对一般实验室完全可承受，方法易于复现与迁移到其他长视频基准。

## 8. 缺点与局限

- **保留集规模过小**：仅 70 个视频的保留集，按四选一选择题计算，1–2 个样本的波动即可改变约 1.4–2.9 个百分点。官方榜单（82.79%）与保留集（81.4%）间的 1.4 pp 差异是否统计显著无法确认，也给 27B 学生（85.7%）与 2B 学生（81.4%）的对比蒙上不确定性。
- **关键消融缺失**：
  - 教师模型多样化（7 种配置）的各自贡献未被单独消融，无法确认 42% 的轨迹来自 gemma-4-31b 是否必要；
  - 未报告合成数据与蒸馏数据按不同配比混合的效果；
  - 未做多随机种子重复，所有结论可能对初始化敏感。
- **“为什么蒸馏初级即可”的解释停留在经验层面**：虽然门控级联统计表明初级一致路径准确率更高（91–95%），但作者没有进一步分析初级模块答错时的错误类型，也未给出“高级模块的轨迹是否本质上不可压缩”的理论论证或更系统的经验证据（如尝试蒸馏高级模块失败的具体案例）。
- **蒸馏数据的规模天花板未探明**：2,936 条轨迹是否已达收益饱和？增加更多蒸馏数据能否继续提升？论文未给出 scaling 曲线。
- **词表修剪的适用范围有限**：该方法依赖一个具体前提——多语言嵌入表占 23% 且任务不需要多语言能力。对于嵌入表占比低或词表本身已被裁剪的模型，该方法提供的参数节省空间有限。
- **先验校正评估引入了新的不确定性**：打乱选项虽然隔离了先验，但也改变了题目原有的干扰项难度分布（原黄金选项位置与干扰项设计可能相关），因此打乱后的保留集成绩可能无法直接外推至原始评测分布。
- **帧采样策略单一**：所有实验均采用均匀采样 100 帧。对于“两跳式”问题，均匀采样是否最优（例如是否应与问题语义相关的内容感知采样结合）未被讨论，而大规模智能体中常用的检索增强式采样恰恰是该方法明确放弃的部分。
- **计算资源披露不充分**：未给出 GPU 型号、总训练时长与教师推理总成本，这使得“低资源”主张的实际程度难以被外界量化评估。

## 9. 论文定位与适用边界

- **适用场景**：参数硬约束（≤2B）下的单次前向长视频 QA；任务可被分解为“均匀采样即可覆盖”的锚点-后续事件型问题；评测集本身存在可被检测的先验分布且允许构建反偏置验证集。
- **不适用场景**：当题目需要精确的时空定位、细粒度动作边界或依赖跨时段非线性整合时（即智能体中高级编排器真正发挥不可替代作用的场景），本方法的压缩前提将失效。
- **该工作的真正贡献**：与其说它提出了一种新的长视频理解架构，不如说它系统地回答了“在 2B 参数约束下，一个工具型智能体流水线的什么部分值得蒸馏”这一问题——其回答是“只蒸馏与最终单次前向协议一致的部分”，并提供了工程上完整的落地方案（分辨率迁移 + 词表修剪 + 先验校正）。

## 10. 总体评价

从竞赛论文的角度看，这是一篇**方法论自觉性高、工程完整度强、评估设计考究**的工作。它没有堆砌新模块，而是在“蒸馏什么”“如何避免先验泄漏”“如何在限制线下凑足参数”三个工程问题上都给出了具有一般性的答案——尤其是“先验泄漏”与“词表修剪”两部分，价值可迁移到其他压缩场景。其不足集中在验证规模与消融粒度上：70 个视频的保留集与单次运行的结论，使论文中最强的两个主张（“2B 达到大型流水线 89% 准确率”“蒸馏初级优于蒸馏全部”）缺乏统计置信度支撑。总体而言，作为一项挑战赛技术报告，质量上乘，方法可复现、可借鉴；作为一篇通用方法论论文，其证据强度尚不足以支撑过于宽泛的结论。

## 11. 可借鉴的经验（对研究者的启示）

1. **蒸馏前先问“输入输出契约能否单次前向表达”**——这一判据比“教师是否强大”更能预测蒸馏收益。
2. **警惕 benchmark 先验随监督信号迁移**——若评测集存在可被穷举猜出的捷径（如固定选项），在构建训练目标时需主动打乱或引入外部数据稀释先验。
3. **负结果是资产**——GRPO 无效、更多帧伤害小模型，这些结论为后续参赛者节省了大量盲目尝试的成本。
4. **在“压缩模型”与“限制参数”之间，词表修剪是一条低风险的工程捷径**——只要残差连接与 LayerNorm 维数不变，逐行复制嵌入即可保证保留路径的确定性等价。
